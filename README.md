## Структуры данных и алгоритмы

### Состояние игры (`src/core/types.ts`, `src/core/state.ts`)

`GameState` — плоский `Readonly`-объект: настройки, секрет (строка, чтобы сохранить
ведущие нули вроде `0123`), `history`, статус и временные метки. История — массив
`readonly HistoryEntry[]`: записи добавляются только в конец и читаются по порядку, поэтому
массив подходит лучше всего. Обновление идёт через `[...history, entry]` и `{ ...state }`,
старый объект не меняется. Если попытка невалидна или повторяется, `submitGuess` возвращает
тот же объект состояния.

### Таблица рекордов (`src/core/scores.ts`)

`Record<"length-base", ScoreEntry[]>`: отдельный топ на каждую комбинацию настроек,
потому что результаты разных настроек несопоставимы. Доступ к нужной таблице — O(1) по ключу.
`addScore` создаёт новый объект, сортирует копию по (попытки, время) и обрезает до топ-N.

### evaluateGuess (`src/core/evaluateGuess.ts`)

Строки приводятся к нижнему регистру и разбиваются на символы. bulls — число позиций, где
`guess[i] === secret[i]` (`filter`). Так как цифры в обеих строках уникальны, число общих
цифр (`filter` + `Set.has`) равно bulls + cows, откуда cows = общие − bulls. Счётчиков и
ручных циклов нет.

### countPossibleSecrets (`src/core/countPossibleSecrets.ts`)

Число размещений P(base, length) = base · P(base−1, length−1), с базой P(·, 0) = 1 и
P = 0 при length > base. Рекурсия вызывает мемоизированную версию самой себя
(`memoize` из `src/core/memoize.ts`, ключ — `JSON.stringify(args)`), поэтому повторные
открытия экрана настроек берут значение из кэша.

## Сложность

L — длина секрета, B — основание системы счисления (L ≤ B).

| Функция              | Время                             | Память   | Обоснование                                                                                                                                            |
| -------------------- | --------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| generateSecret       | O(L·B)                            | O(L·B)   | L рекурсивных шагов; на каждом `filter` по пулу размером ≤ B создаёт новый массив (иммутабельность), и эти массивы живут в стеке до выхода из рекурсии |
| evaluateGuess        | O(L)                              | O(L)     | построение `Set` и два прохода `filter`, `Set.has` — O(1)                                                                                              |
| isValidGuess         | O(L + B)                          | O(L + B) | валидатор строит `Set` из B символов один раз, затем `every` и `new Set` — по L символам                                                               |
| countPossibleSecrets | O(L) первый вызов, O(1) повторный | O(L)     | L рекурсивных вызовов с O(1) работой каждый; результаты (l, b) лежат в кэше                                                                            |

В нашей задаче L ≤ 6 и B ≤ 16, поэтому все функции выполняются мгновенно.

## Принципы чистого кода

- **Одна ответственность:** один файл — одна функция (`src/core/*.ts`); UI-экраны
  разделены на `settingsScreen.ts`, `gameScreen.ts`, `leaderboard.ts`.
- **Говорящие имена:** `isLengthAvailable`, `normalizeSettings`, `takeUnique`, `formatDuration`.
- **Отсутствие магических значений:** алфавит, длины, лимит таблицы, ключ хранилища —
  в `src/core/config.ts`.
- **DRY:** `createDigitValidator` используется в `isValidGuess` и в `gameScreen.ts`
  (фильтр ввода); `memoize` переиспользуем.
- **Чистые функции и иммутабельность:** вся логика в `src/core` без DOM, без классов и
  без мутаций; побочные эффекты (DOM, localStorage, таймер) только в `src/ui` и `main.ts`.
- **Ранние возвраты (guard clauses):** `submitGuess` проверяет статус, валидность и дубль
  по очереди и выходит сразу.
- **Явные типы:** `Readonly`-типы в `src/core/types.ts`.
